# Build Procedure

## Strategy

Build the desktop browser version and Django backend first, deploy them early, then move toward iPhone support after the web product is useful.

The desktop web app should also support small browser windows and mobile browsers through responsive design. This allows the first product to work on phones before investing in a native iPhone application.

## Recommended Order

```text
Phase 1: Desktop web UI with responsive layout
Phase 2: Django backend, auth, API, and Oracle Database
Phase 3: Deploy frontend and backend
Phase 4: Polish mobile browser layout
Phase 5: Convert to installable PWA
Phase 6: Build native iPhone app if still needed
```

## Phase 1: Desktop Web UI

Core layout:

- Left sidebar for navigation.
- Main task list.
- Right task detail panel.
- Top input or command area for fast task creation.

Responsive behavior:

- Sidebar becomes a drawer or bottom navigation on small screens.
- Task detail panel becomes a full-screen detail view on small screens.
- Buttons and list rows become easier to tap.
- Text and controls must fit cleanly in narrow windows.

## Phase 2: Backend

Use Django for the shared backend.

Backend responsibilities:

- User authentication.
- Oracle Database on OCI.
- REST API for web and future iPhone clients.
- Task persistence.
- Object-level permissions so each user only sees their own data.
- Optional realtime or notification support later.

Recommended backend stack:

- Django.
- Django REST Framework.
- Simple JWT.
- Oracle Database.
- django-cors-headers.
- django-environ or python-dotenv.

## Phase 3: Deployment

Use Vercel for the Next.js web app. Deploy the Django backend to an Oracle Cloud Infrastructure Always Free VM. Use Oracle Database on OCI for production data.

Initial deployment shape:

```text
Desktop browser
Mobile browser
        |
        v
Next.js app on Vercel
        |
        v
Django REST API
        |
        v
Oracle Database on OCI
```

Deploy early so the product can be tested in real life instead of staying local.

## Phase 4: Mobile Browser Polish

After the deployed web version works, improve the small-screen experience.

Focus areas:

- Mobile navigation.
- Large tap targets.
- Task creation speed.
- Full-screen task detail view.
- Smooth keyboard behavior.
- Readable list density.

## Phase 5: PWA

Turn the web app into an installable Progressive Web App if the browser version is useful.

## Phase 6: Native iPhone App

Build a native iPhone app only if the PWA is not enough.

Use React Native or Expo if native is needed. Keep the same Django API so the web and iPhone apps share users, tasks, and data.
