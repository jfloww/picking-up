# Design Patterns

## Direction

Use a modern product architecture that is common in larger software teams:

- Feature-based frontend architecture.
- Reusable UI component system.
- Typed API access layer.
- Django and Django REST Framework as the backend foundation.
- Oracle Database on OCI as the production database.
- Backend permission checks at the API boundary.
- Versioned Django migrations.

## Frontend Pattern

Use feature-based architecture instead of grouping everything only by file type.

```text
frontend/
  src/
    app/
    features/
      auth/
      tasks/
    components/
      ui/
      layout/
    lib/
      api/
      utils/
```

## Backend Pattern

Use Django REST Framework as the API boundary.

```text
Client UI
  |
  v
Typed frontend API functions
  |
  v
Django REST API + permissions
  |
  v
Oracle Database on OCI
```

## Backend Structure

```text
backend/
  manage.py
  requirements.txt
  .env.example

  config/
    settings.py
    urls.py
    wsgi.py
    asgi.py

  apps/
    accounts/
    tasks/
```

## Data Access Pattern

Use repository-style functions on the frontend for backend operations.

Example task operations:

- `getTasks`
- `getTaskById`
- `createTask`
- `updateTask`
- `completeTask`
- `archiveTask`
- `deleteTask`

UI components should call these functions instead of scattering raw `fetch` calls everywhere.

## Security Pattern

Use Django REST Framework permissions and query filtering.

Security rules:

- Every task belongs to a user.
- API list endpoints only return the current user's tasks.
- API create endpoints assign ownership from `request.user`.
- Users can only read their own tasks.
- Users can only update their own tasks.
- Users can only delete their own tasks.

Authorization should not depend only on frontend checks.

## Chosen Standard

```text
Frontend: Feature-based architecture + reusable UI components
Backend: Django REST Framework + service/repository-style logic + permissions
Database: Oracle Database on OCI + Django migrations
Product: Desktop web first, responsive small-window support, PWA/iPhone later
```
