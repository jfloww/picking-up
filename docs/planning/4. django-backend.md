# Django Backend Plan

## Direction

Use Django as the shared backend for the desktop web app and future iPhone app.

The backend owns authentication, authorization, task data, migrations, and API contracts. The frontend and future mobile app should both call the same API.

## Stack

- Django.
- Django REST Framework.
- Simple JWT.
- Oracle Database on OCI.
- django-cors-headers.
- django-environ or python-dotenv.
- pytest or Django test runner.

## Runtime Architecture

```text
Next.js web app
        |
        v
Django REST API
        |
        v
Oracle Database on OCI

Future iPhone app
        |
        v
Same Django REST API
        |
        v
Same Oracle Database
```

## Auth API

Start with JWT authentication.

```text
POST /api/auth/register/
POST /api/auth/token/
POST /api/auth/token/refresh/
GET  /api/auth/me/
```

## Task API

```text
GET    /api/tasks/
POST   /api/tasks/
GET    /api/tasks/{id}/
PATCH  /api/tasks/{id}/
DELETE /api/tasks/{id}/
POST   /api/tasks/{id}/complete/
POST   /api/tasks/{id}/archive/
```

## Task Model

```text
id
user
title
description
status: todo | done | archived
priority: low | medium | high
due_date
created_at
updated_at
completed_at
```

## Permission Rules

- API requests must be authenticated unless explicitly public.
- Users can only list their own tasks.
- Users can only read their own tasks.
- Users can only update their own tasks.
- Users can only delete their own tasks.
- Task ownership is assigned by the backend from `request.user`.

## Deployment Direction

```text
frontend/ -> Vercel
backend/  -> Oracle Cloud Infrastructure Always Free VM
database  -> Oracle Database on OCI
```

For early development, SQLite is acceptable only as a temporary local fallback. Before deployment, configure Django to connect to Oracle Database and run migrations there.
